# 数据管理

## 文件和编辑

原始数据为 MCAP，ROS 消息保存为 CDR 并包含消息定义。`/humanoid/annotations`、`/humanoid/data_quality` 保存管理器产生的 JSON 事件。录制文件包含机器人配置版本、配置指纹、接收端配置摘要、ROS 域和录制设置指纹。

同名录制自动添加时间戳；导出、修复和上传拒绝覆盖同名文件。删除录制时一并清理相关标记文件。正在写入的文件不能下载、回放、编辑或删除。

| 文件 | 用途 |
| --- | --- |
| `name.mcap` | 原始消息、在线标记、诊断事件和会话元数据 |
| `name.mcap.edit.json` | 当前离线编辑、时间裁剪、备注和片段标记；使用版本标识防止并发覆盖 |
| `name.mcap.session.json` | 在线标记与异常的额外落盘副本，便于写入进程异常退出后的核对 |
| `name.mcap.quality.json` | 最近一次数据扫描报告；源文件发生变化后失效 |

默认导出只保留裁剪范围内、未被任何无效片段覆盖的消息。有效标记用于分类，不覆盖重叠的无效标记。端点包含在片段内。原始消息字节、话题类型和时间戳保留，消息之间原有时间间隔保留；编辑配置与来源写入 `humanoid_manager.edit` 元数据。需要分享离线编辑而暂不导出时，请同时保存 MCAP 及配套编辑 JSON。

## 回放

回放是网页数据预览，不发布机器人运动命令。支持时间跳转、暂停、倍速、关节曲线和消息内容。预览按话题限频以控制浏览器负载；文件中的原始消息不受影响。

ROS CDR 预览需要本机安装对应消息类型。缺少自定义消息类型时显示具体解码错误，仍可按原始消息裁剪与导出。图像和点云保留在 MCAP 中参与录制与裁剪，目前网页不解码显示其像素/点阵。

## 异常

录制时每秒检查一次健康状态，话题超过约 1.8 秒无新数据判为中断，再随下一次健康检查落盘。每次状态变化写一条事件，避免重复日志淹没数据。界面显示丢弃消息数、写入错误和最近异常。

“检查数据异常”顺序扫描完整文件，验证 CRC 与解码，检查非有限数值、同一通道时间戳倒退。录制表中的“异常间隔”大于零时，也检查该话题最大消息间隔。统计保留全部计数，页面展示前 200 条问题。它不判断动作是否完成、物理运动是否正确；操作者可结合回放把片段标为无效。

“修复副本”从头读取到首个损坏处，将完整可读消息写入新的 MCAP，并报告恢复数量和停止原因。损坏的压缩块及之后的消息可能不能恢复；不会补造消息或覆盖原文件。磁盘空间不足时先处理空间问题，再修复副本。

## 接口

所有接口与网页同源；默认只监听本机。

| 接口 | 用途 |
| --- | --- |
| `GET /api/status` | ROS、录制、回放、按钮和异常状态 |
| `GET /api/settings` | 系统草稿、已保存配置、当前运行配置及版本标识 |
| `POST /api/settings/{draft,save,apply,restore}` | 系统配置编辑、保存、应用与恢复 |
| `GET /api/adapters` | 插件和机器人配置目录 |
| `POST /api/recording/{start,stop,mark}` | 开始/停止录制与在线标记 |
| `GET /api/datasets/{filename}` | 文件概要、标记、裁剪和扫描报告 |
| `GET /api/datasets/{filename}/frames?start=0&end=1&limit=100` | 时间范围内最多 500 条预览消息 |
| `POST /api/datasets/{filename}/{edit,export,audit,recover}` | 保存编辑、另存导出、检查与修复 |
| `POST /api/replay/{play,pause,seek,stop}` | 网页回放控制 |
| `GET /ws` | 实时 ROS 观察和网页回放事件 |

编辑与导出请求需要当前文件的 `etag`；编辑载荷含 `notes`、`trim:{start,end}`、`annotations:[{id,label,start,end,note}]`，时间单位为秒，从文件第一条消息计时。`label` 为 `valid`、`invalid` 或 `note`。
